# 決定事項(v1.0 の「8. 未確定・次のステップ」への回答)

要件定義書 v1.0 で未確定だった4点について、以下の通り確定した。

## 1. 新規DBをどのページ配下に作成するか
新規に親ページ(仮称「マラソン管理」)をNotionワークスペース直下に作成し、その配下にDBを配置する。
既存ページとの紐付けは行わない。作成手順は `notion/setup_db.py` と `docs/notion-schema.md` を参照。

## 2. iPhoneショートカットの具体的な設計
発話テキストのパース(自動解析・自動分類)は行わない。理由: パース処理はロジックが複雑になり誤判定のリスクがある上、非機能要件「数秒で完結」を損なう。
代わりに以下の2ステップ構成にする。
1. 「食事種別(朝食/昼食/夕食/間食)」をメニューからワンタップ選択
2. 内容は音声入力(Dictate Text)でそのまま自由記述として保存

詳細は `docs/iphone-shortcuts.md` を参照。

## 3. コンディション系ナッジの通知トリガー時刻
- 朝の通知: 7:00
- 夜の通知: 21:30

iPhone標準の「オートメーション」機能(時刻トリガー、実行前に確認 = ON)で設定する。詳細は `docs/notifications.md` を参照。

## 4. ピーキングフラグの切り替え方法
手動切り替えを採用する。ただし日々の入力に手間を増やさないため、次の方式にする。
- ピーキング中かどうかを iCloud Drive 上の小さなフラグファイル(`Shortcuts/peaking_flag.txt`)に保持する
- 専用の「ピーキング切替」ショートカット(ホーム画面に1つ配置)で、レース前2〜3週間の開始時と終了時に1回ずつON/OFFを切り替える
- 朝・夜のナッジ、食事ログのショートカットは毎回このファイルを読み取り、現在のフラグ値をNotionへの書き込みに含める(日々の追加タップは発生しない)

詳細は `docs/iphone-shortcuts.md` の「ピーキング切替ショートカット」を参照。
